SECTION 1: THE ARCHITECTURAL CHALLENGE Slide 2 of 6

The Core Problem: Why Do We Need Adapters?

In a Telecom Digital Twin, each system speaks a totally different language and operates on radically disparate timescales. Without adapters, co-simulation and automated closed-loop control are impossible.

1. DECLARATIVE INTENT TMF921
Operator / SLA Goal

High-level expectations expressed in Natural Language or structured JSON contracts.

Speaks: Business SLA
Timescale: Minutes → Days
"Keep URLLC < 1.5ms during rain storms"
2. SDN CONTROLLER ETSI TFS
Network Orchestration

Topology graphs, device inventories, endpoint UUIDs, and constrained path calculation (CSPF).

Speaks: Graphs & gRPC
Timescale: Seconds
34 nodes, 34 links, TI-LFA backup paths
3. DISCRETE SIMULATOR NS-3.45
Packet Dynamics & Queues

Discrete-event scheduling: bufferbloat, EDCA contention, packet drops, and jitter.

Speaks: C++ Events & Trace
Timescale: Microseconds (μs)
t = 0.042180s, Queue 150/150 TAIL-DROP
4. PHYSICAL HARDWARE Ceragon HW
Microwave Transceiver

Siklu MultiHaul MH-T261 (192.168.1.225): V-band 60 GHz, ACM modems, PHY registers.

Speaks: RESTCONF & PHY
Timescale: Hardware Realtime
60.48 GHz, MCS 8 (64-QAM), -58.4 dBm

Adapters are the Semantic Bridges

SECTION 2: INTERNATIONAL STANDARDS ALIGNMENT Slide 3 of 6

Standards for Digital Twin APIs We Use & What They Are MANDATORY COMPLIANCE

The digital twin does not use proprietary protocols. Every single interface is mapped directly to international telecom standards across TM Forum, 3GPP, ITU-T, IETF, and ETSI.

TM FORUM TMF921 INTENT NBI
Intent Management REST API

What it is: Global telecom specification defining declarative SLA contracts, lifecycle states, and compliance tracking.

In Our System: Ingests latency ≤ 1.5ms, tracks state (INGESTED → EVALUATING → COMPLIANT).
3GPP TS 28.561 5G/6G NDT
Network Digital Twin Lifecycle

What it is: 3GPP Release 18/19 architecture defining closed-loop validation, safety envelopes, and autonomous assurance.

In Our System: Governs the 4-Phase Pre-Flight Safety Gate (Latency, Queue Stability, Hardware, Spectral Mask) before actuation.
ITU-T Y.3090 DTN ARCHITECTURE
Digital Twin Network Reference Model

What it is: ITU-T 3-layer reference model (Physical Network ↔ Digital Twin Layer ↔ Network Application Layer).

In Our System: Dictates the Shadow Datastore Synchronization protocol keeping cyber representations in sync with live microwave hardware.
IETF NMRG DTI SIMULATION SBI
Digital Twin Interface (RFC Draft)

What it is: IETF research standard for Twin-to-Simulator East-West communication and model fidelity negotiation.

In Our System: Standardizes perturbation dispatch (traffic surge, rain fade) and discrete packet trace streaming from NS-3.
IETF RFC 8040 & 7950 HARDWARE SBI
RESTCONF Protocol & YANG 1.1

What it is: HTTP-based interface to YANG datastores offering Candidate staging and atomic 2-Phase Commit (2PC).

In Our System: Drives Ceragon MH-T261 (192.168.1.225:80) via PATCH candidate → POST commit.
ETSI TERAFLOWSDN SDN CONTROL
Cloud-Native Microservices Pipeline

What it is: ETSI open-source controller architecture for autonomous optical and microwave transport networks.

In Our System: Context (:10010), Service/PCE (:10030), Device Driver (:10020), Monitoring (:10040).
All 6 standards are actively exercised in both the Standalone Evaluator and Physical Lab deployments.
SECTION 3: HOW ADAPTER 1 FUNCTIONS Slide 4 of 6

Adapter 1: TFS-to-NS-3 Simulation Adapter THE CYBER MIRROR

This adapter bridges ETSI TeraFlowSDN's live macroscopic network topology with the microsecond-accurate C++ discrete event simulation core on efid@cersrv-029.

01
Topology & Telemetry Sync

Queries TFS Context (:8088) to fetch the 34-node carrier graph, link capacities, and Ceragon RF metrics (RSSI -58 dBm, MCS 8).

02
Simulation Governor (Scoping)

Rather than simulating all 34 nodes (which takes minutes), scopes to Tier 4: URLLC Slice (23 nodes, 95% fidelity) executing in ~1,150ms.

03
What-If Perturbation Dispatch

Injects stress: a 3.5x bulk traffic burst on STA 1 (bufferbloat) or ITU-R P.838 rain fade (dropping modulation from 1Gbps to 100Mbps).

04
Discrete Trace & NetAnim XML

Generates /tmp/tsn_wifi_ceragon_anim.xml and streams microsecond queue depths, tail-drops, and packet transit times back to the twin.

🎮 NETANIM VISUALIZATION

Instruments 10 visual buffer slots at Ceragon Node 0 with flashing RED tail-drop alerts when queues hit 150/150 under surge.

🛡️ DETERMINISTIC TSN MAPPING

Maps IEEE 802.1Q PCP Class 6 & WiFi EDCA AC_VO directly into PfifoFast Band 0 strict priority queues.

🚀 HYBRID LOCAL / REMOTE

Dispatches to remote Ninja build on efid@cersrv-029, with instant fallback to local analytical engine for GitHub clones.

SECTION 4: HOW ADAPTER 2 FUNCTIONS Slide 5 of 6

Adapter 2: TFS Southbound & Hardware Driver Adapter THE PHYSICAL ACTUATOR

How decisions are safely translated from the cyber twin into physical Ceragon microwave transceivers without ever endangering production customer traffic.

PHASE 1: STAGING RFC 8040 CANDIDATE
Candidate Datastore Staging

The decision engine proposes mitigation rules. The adapter stages them in ETSI TeraFlowSDN's Candidate Datastore (isolated from running traffic):

  • ✓ ACM Floor Hardened: ≥ MCS 4 (≥ 500 Mbps)
  • ✓ QoS Queue: PCP Class 6 (Band 0 Strict)
  • ✓ Frequency: 64.80 GHz (Interference avoidance)
PHASE 2: VERIFICATION 3GPP TS 28.561
Pre-Flight Safety Envelope

Before touching physical hardware, the adapter validates candidate changes against 4 strict envelope gates:

  • ✓ Gate 1: Latency Bound Pass (1.12ms ≤ 1.5ms)
  • ✓ Gate 2: Queue Stability Pass (Buffer < 40%)
  • ✓ Gate 3: HW Capability Pass (MH-T261 supports MCS 4)
  • ✓ Gate 4: Spectral Mask Pass (Approved V-Band channel)
PHASE 3: 2PC ACTUATION RESTCONF COMMIT
Atomic 2-Phase Commit (2PC)

The adapter issues an atomic two-phase commit over HTTP/RESTCONF to physical socket 192.168.1.225:80:

  • → Step 1: PATCH candidate datastore
  • → Step 2: POST ietf-netconf:commit
  • → Step 3: Continuous RFC 8040 telemetry sync
  • → Failover: Instant rollback if telemetry breaches
🔒 Zero-Outage Guarantee: Staged datastores + discrete verification guarantee that destructive configurations are rejected in software before hitting production transceivers.
